# Safety policy workspace checkpoint — 20 September 2026

This checkpoint extends the safety-review workflow with editable policies, optional simulation, persistent drafts, inspectable results and UI refinements. Earlier hook blocking, human approval, notification and latency-budget work is described in [RFC 006](rfc-006-safety-performance.md). This document records the final behavior, including changes made after the initial policy implementation.

## Policy engine and lifecycle

- Action normalization is separated from matching. Rules cover file reads/writes, shell commands, detected Git pushes, sensitive-file access, detected network requests and exact tool names.
- Rules support all connections or a selected set, resource/working-directory scopes, filename/extension conditions and literal command conditions. See [policy boundaries](policies.md) for limitations.
- Custom precedence is Block → Ask me → Send to judge → Approve automatically. Built-in prohibitions take precedence. Unmatched requests retain normal judging.
- Fast automatic approval remains restricted to verified scoped direct file reads. Deterministic decisions avoid model queuing; human-review policies route directly to approval.
- One persistent draft collects edits, removals and enabled-state changes. Applying updates new requests only. Revision checks reject stale writes; tested snapshots retain their evidence.
- Applied history exposes actual changes and Restore as draft. Pause retains the applied set; Resume restores it. Pausing does not delete rules.
- Past simulation and live simulation are optional and independent. Application no longer requires a preview. The browser warns before applying a draft without a past simulation; operators can dismiss this warning permanently for that browser and restore it in Safety settings → Policies.

## Policy workspace

Presets live in the editor. The main rule list contains enable/disable pill switches, edit and remove controls. Switches stage draft changes; applying remains explicit. During a switch save, conflicting controls remain disabled but keep their appearance, avoiding the former blue-button flash.

Discard, remove and review use compact dialogs. History has one toggle and no duplicate Close action. Change dialogs fit their contents. Paused rules remain in place with muted styling and struck-through names. A single labeled priority chain replaces repeated pairwise overlap cards. Routine application no longer produces a large success banner.

Simulation uses a permanent Past requests / Live requests selector with one action for the chosen mode. Controls do not appear or disappear based on whether a simulation has already run. Prerequisite/explanation labels were removed. Mobile controls and row actions remain grouped and reachable above the bottom navigation.

## Simulation evidence

Past simulations retain up to 500 recent assessments; live results show the latest 1,000 records for the tested version. Outcome cards filter the retained sample, search matches action/session/rule details, and results paginate in groups of 20. Select a result to see its saved redacted request, recorded assessment, proposed decision, matching conditions and winning-rule explanation. Explanations reflect the actual priority winner, including Review and Judge decisions, rather than always claiming Block won.

Results distinguish unavailable evidence and unmatched requests. Built-in evidence comes from the assessed snapshot. Older previews without detailed items must be rerun. Simulations execute no tool actions and do not call the model. Saved inputs and current filesystem checks do not reconstruct historical filesystem state or establish classifier accuracy.

## Debug and related fixes

Debug can force Allow, Review or Deny without Anthropic calls; the setting is captured per assessment. Custom policy shortcuts originally ran before the debug setting was read, causing Debug Allow to reach manual review. Debug now precedes custom-policy routing while built-in prohibitions, incomplete-action restrictions and deadlines remain enforced. Turning debug off restores the configured policy path. Debug assessments are separated from production metrics. New local requests were verified as completed with debug attribution after the fix.

Safety charts and action lists refresh together. Relative ranges such as Last hour remain rolling across polling and navigation, with bounds resolved once per backend request. Explicit ranges and inspected buckets preserve exact bounds. Add connection is confined to Connections. Action headings identify the tool request and label the session context rather than presenting an unexplained session title.

## Storage and rollout

Migrations 0011–0014 add debug settings, editable policy state/history, persistent draft/preview data and paused-policy retention. Existing version evidence is retained. Local migration work used a SQLite backup; restarts checked for no queued/running/awaiting-review assessments. Local configuration, policy records and debug preferences were not copied into source control.

For another checkout, install the existing dependencies, run `.venv/Scripts/python.exe -m alembic upgrade head`, build the frontend, and restart the API and worker using the project instructions. No API keys, local databases, logs, screenshots or generated frontend assets are included in this checkpoint.

## Review and verification

System-design and iterative UI/UX reviews covered policy scope, draft lifecycle, decision explanations, simulation, confirmations, paused rules, desktop and mobile layouts. Follow-up findings were addressed. Regression coverage includes delayed saves (button appearance remains stable), optional simulation and warning reset, persistent pause/resume, draft restore, result search beyond the first ten records, pagination and debug precedence over custom policies.

Final checkpoint verification: **185 backend tests passed**, **29 Playwright browser tests passed**. TypeScript and the production build passed during the final implementation; the build retains its existing large-bundle warning. Tests use synthetic data and isolated databases; they make no paid judge calls and execute no simulated user commands.

## Remaining work

This is a single-host PoC. Strong executor isolation, authenticated operators, a policy store outside the monitored OS account, distributed queues/quota control, service-backed notifications, incident ownership and broader accuracy/latency evaluation remain future work. Shell-signal detection is conservative and cannot understand arbitrary scripts or encoded commands. Automatic file-read approval cannot eliminate filesystem changes between checking and execution. Browser warning preferences are local to that browser. See RFC 006 for the larger roadmap.

## Follow-up: chart scale control

A browser regression switches color and interval controls, verifies Scale stays enabled, and checks that logarithmic mode changes bar geometry for Actions and Messages.
